
# 模倣学習と実機評価　　2026/11/13-11/13

### 3-1 学習環境の確認

Windows上のWSL2／Ubuntu環境で、LeRobotとPyTorchによるGPU学習が実行できることを確認した。

| 項目 | 確認結果 |
|---|---|
| 実行環境 | WSL2／Ubuntu、Python仮想環境 `lerobot` |
| Python | 3.12.3 |
| LeRobot | 0.6.1 |
| PyTorch | 2.11.0+cu130 |
| GPU | NVIDIA ***** 、VRAM ** GiB |
| PyTorchのCUDA利用 | `True` |
| Accelerate | 1.15.0（不足していた依存関係を追加） |
| 依存関係検査 | `No broken requirements found.` |

CUDAを使った小規模な行列計算、ACT本体の読み込み、学習処理の動作確認を行った。学習には保存済みデータを用いた。

#### 環境構築時に対応した点

- `accelerate`が未導入で学習開始に失敗したため、依存関係を追加して再確認した。
- データセット作成時、`RGBEncoderConfig`に指定した`libx264`はこの環境では受け付けられなかった。設定値を`h264`に変更して作成を完了した。
- 使用中のLeRobotのソースと設定を確認し、インストール済みバージョンに合わせてスクリプトを作成した。

**結果：GPUでACTの学習を実行できる環境を確認した。**

### 3-2 模倣学習と評価

収集した実演データ20件を使ってACT（Action Chunking with Transformers）を学習した。学習済みモデルを実機で評価し、黄緑のワークをつかんで赤い入れ物へ置くタスクの初回成功を確認した。

#### 学習設定

ACTはカメラ画像と関節状態を入力し、複数ステップ分の動作をまとめて予測するモデルである。今回は以下の設定で学習した。

| 項目 | 設定 |
|---|---|
| データセット | `local/so101_yellow_pick_place_20_trimmed_v1` |
| 分割 | 学習16エピソード、評価4エピソード |
| 学習データのフレーム数 | 12,720 |
| 入力 | 作業領域のRGB画像1枚＋6要素の関節状態 |
| 出力 | 6要素のaction |
| 画像バックボーン | ResNet-18、ImageNet事前学習重み |
| 学習ステップ数 | 10,000 |
| バッチサイズ | 2 |
| 学習率 | `1e-5` |
| 数値精度 | FP32（`use_amp=false`） |
| `chunk_size` / `n_action_steps` | 100 / 100 |
| Temporal ensemble | 使用しない |
| 評価間隔 | 2,000ステップ |
| 保存間隔 | 5,000ステップ |
| seed | 42 |

学習は約36分29秒で終了し、終了コードは0だった。

#### オフライン評価

| ステップ | eval_loss |
|---:|---:|
| 2,000 | 0.4850 |
| 4,000 | 0.4688 |
| 6,000 | 0.3989 |
| 8,000 | **0.3944** |
| 10,000 | 0.4118 |

評価損失の最小値は8,000ステップ時点だった。ただし、今回の保存設定では5,000ステップと10,000ステップのモデルのみ保存しており、8,000ステップのモデルは残っていない。実機評価には10,000ステップのモデルを使用した。

```text
act_16train_4eval_fp32_20261113_161537/checkpoints/010000/pretrained_model
※容量が多いので、ここには保存していません。
```

次回は評価のタイミングに合わせたチェックポイント保存、または評価損失が最小となったモデルを保存する処理を用意する。評価損失と実機での作業成功率は別の指標として扱う。

#### 実機評価の経過

短時間の動作確認から開始し、接近方向、把持、運搬、配置を確認した。途中では、把持位置のずれ、開始位置付近で動かない、把持できても制限時間内に運搬まで進まない、といった結果があった。

照明と開始姿勢も試行間で変化しており、失敗の原因をいずれか1つに断定できる比較にはなっていない。

開始姿勢を調整し直した後、45秒の試行では把持に失敗して赤い入れ物へ移動し、その後ワークへ再接近したところで時間切れとなった。次の試行ではプログラムの制限時間を60秒に変更し、タスクの成功を確認した。再接近した動きだけから、モデルが把持失敗を認識したとは判断していない。

実際にロボットが動いたACT評価を数えると、**10回目で初めてタスクを完遂した**。この回数には短時間の確認試行を含み、接続エラーで動かなかった回や姿勢合わせ・肘の単独試験は含めない。最後の姿勢調整後では2回目の評価だった。

試行時間や開始条件を変更しながら進めた開発中の評価であるため、この記録を「同一条件で10回評価した成功率10%」とは扱わない。

#### 今回わかったことと次の課題

- **初回成功を確認した。** 同じ条件で繰り返し評価した再現性・成功率の測定は未実施。
- 次回は開始関節値、ワーク位置、カメラ画角、照明を記録してそろえ、変更項目を1つずつにする。
- 関節角度を目標値へ合わせるだけでは、途中の経路が机に接触する可能性がある。今回の自動姿勢合わせでも接触が発生したため、経路を確認せずにそのまま再利用しない。
- キャリブレーションの不一致が繰り返された。保存値の復元と読み戻し一致は確認したが、電源再投入後の保持については継続確認が必要。
- 日中の収集と夜間の評価で照明条件が異なった。照明の影響は単独では切り分けられていない。
- 評価損失が最小のモデルを保存し、最終ステップのモデルと比較できるようにする。
